# Руководство Нового Разработчика (Onboarding)

Добро пожаловать в команду разработки TmWork! Этот документ — ваша отправная точка. Проект сложный, имеет глубокую финансовую логику и систему ролей, поэтому **пожалуйста, прочитайте этот документ до того, как начнете писать код.**

---

## 🏗 Общая Архитектура

Проект построен по принципам **Decoupled Architecture** и **Clean Code**:
- Вьюхи (`views.py`) — максимально **тонкие**. Они только принимают реквест, вызывают нужный сервис и возвращают ответ от сериализатора.
- Бизнес-логика живет в **Service Layer** (`services.py`).

### Структура Приложений (Django Apps)
- **`users`**: Базовая авторизация (Email вместо username), роли и доступы.
- **`profiles`**: Публичные данные (Аватар, рейтинг, биография).
- **`jobs`**: Публикация заказов и откликов. Жизненный цикл заказа (DRAFT -> PUBLISHED -> IN_PROGRESS -> COMPLETED).
- **`escrow`**: Безопасные сделки. Удержание средств клиента до завершения работы.
- **`transactions`**: Запись ВСЕХ денежных движений. (Только для добавления, изменения запрещены).
- **`core` / `ml`**: Хранит встроенные сервисы ИИ-ранжирования.

## 💰 Финансовая Логика (Самое важное!)

**КРИТИЧЕСКОЕ ПРАВИЛО:** В TmWork **строго запрещено** напрямую менять поле `balance` у профиля во вьюхах.

Мы работаем с деньгами. При высокой нагрузке (например, два одновременных вывода средств) возможны состояния гонки (Race Conditions), когда баланс уходит в минус из-за того, что два процесса прочитали старое значение баланса.

**Как правильно работать с балансом:**
Всегда используйте `Profile.objects.select_for_update()` — это накладывает Row-Level Lock (блокировку строки БД), пока транзакция не завершится.
*Вам не нужно писать это вручную, просто всегда вызывайте метод `TransactionService.process_transaction()`, он уже инкапсулирует эту логику и делает проверки.*

## 🤖 Как работает Искуственный Интеллект (Smart Match)

В проекте есть двухконтурная ИИ-система (Лента и Поиск). 
Вам не нужны знания Data Science, чтобы работать с ней, так как она интегрирована прозрачно.

Логика находится в `backend/apps/core/services/ml_service.py`.
1. **Fallback (Встроенный алгоритм)**: При старте Django, `ml_service` включает эвристический алгоритм (вес: 40% навыки, 25% рейтинг и т.д.). Никаких сторонних библиотек (`pandas`, `sklearn`) не требуется.
2. **Эксперименты (Trained Model)**: Если в папке `ml/` (вне папки `backend/`) доступна обученная модель, `ml_service` "подхватит" её и начнет пропускать данные через нейросеть / Random Forest.

## 🔐 Роли и Доступы (Permissions)

В TmWork один аккаунт (`User`) может легко переключаться между интерфейсом КЛИЕНТА и ФРИЛАНСЕРА. Права доступа зависят от контекста.

Во `views.py` всегда используйте классы из `apps.users.permissions`:
- `IsClient()` — доступ только клиентам (например, создать заказ).
- `IsFreelancer()` — доступ только фрилансерам (например, откликнуться на заказ).
- `IsJobOwner()` — доступ только создателю заказа.

## 🛠 Гайдлайны по разработке (Checklist)

### Быстрый старт с тестовыми данными
Чтобы не сидеть с пустой платформой после клонирования репозитория и миграции базы, запустите встроенный скрипт инициализации:
```bash
uv run python scripts/initialize_dev_data.py
```
Он автоматически создаст несколько категорий заказов, суперпользователя (Админа), тестового Фрилансера и тестового Клиента (пароль у обоих: `TestPass123!`).

### Перед тем как отправить пулл-реквест (Pull Request):
1. **Migrations**: Вы точно не забыли `python manage.py makemigrations`? Если добавили поле и залили код без миграции, Prod упадет.
2. **Throttling**: Если написали новый публичный API-эндпоинт (особенно где можно зарегистрироваться или создать пост), добавьте Rate Limiting (Throttle Classes), чтобы нас не "заспамили".
3. **N+1 Queries**: Всегда используйте `select_related` и `prefetch_related` в `get_queryset()` во вьюхах.
4. **Секреты**: Никаких захардкоденных токенов или паролей в коде! Всё читается из `.env`. Файл `.env` **строго запрещено** пушить в Git (он добавлен в `.gitignore`).

**Удачи в разработке!** Если что-то сломалось на уровне архитектуры — обратитесь к файлу `API_DOCUMENTATION.md` или к ведущему архитектору.
